# 排版语义复查准则

> 这份文档定义「排版正确」的标准。agent 逐篇复查时按此判断，不要凭感觉。
> 所有判据都经过 1241 篇已验收存量库反标定，写在这里的阈值是有实测依据的。

## 0. 排版到底做了什么

`md_layout.py` 把 PDF 的**物理行**重排成**逻辑自然段**。

**源 PDF 的真实形态**（实测结论，务必理解）：

- PDF 文本层**基本没有空行**（1241 篇抽样 40 篇：1582 行里只有 3 个空行，0.19%）。
- PDF 文本层**没有缩进**（所有行 x0 一致，全是左对齐硬折）。
- 所以**源 PDF 里根本没有段落信息**——排版规则是靠「行尾标点」来推断段落的。

排版规则（`md_layout.rebuild`）：

- 行尾有终止标点（`TERMINATORS`：`。！？；：…—）》」』】”"．` 等）→ 断段
- 行尾没有终止标点 → 与下一行无缝拼接（因为那是 PDF 硬折造成的半句）
- 原文中的空行 → 段落边界（仅当空行密度 > 0.15，即「已排版/OCR 型」文件才严格生效）

**因此排版错误只有两种形态**：该断的没断（多段并成一段），不该断的断了（一句被切成两段）。

## 1. 判断材料

每篇复查需要（由 `export_review.py` 导出到 `/tmp/chaguan_review/<stem>/`）：

| 文件 | 作用 |
|------|------|
| `md.md` | 排版后的 Markdown，**待检对象** |
| `src.txt` | 源 PDF 的物理行，**判断依据**。每行前缀标记：`[断]`=行尾有终止标点（排版会在这里断开）、`[续]`=硬折半句（排版会与下一行拼接）、`[页末]`=页与页之间 |
| `para_map.json` | MD 段落序号 → 源物理行区间（`src_range` 为 1-based 闭区间；`null` 表示该段来自页内非行结构，如表格） |
| `meta.json` | 正文字符数、段落数、源 PDF 路径 |

**关键**：判断分段对错**必须对照 `src.txt`**。只看 `md.md` 无法区分：
- 「一句被错误切成两段」（两段都很怪）
- 「原文本来就是两个独立段落，只是恰好都短」（两段都正常）

`src.txt` 里 `[断]` 标记的行 = 排版规则会在这里断开。**相邻两个 `[断]` 之间 = 一个排版段落**。
若 `para_map` 显示某段跨了多个源行，说明这些行是被拼接的（`[续]` 行）。

**纯图片 PDF 的例外**：部分早期文章是图片版（无文本层），MD 来自历史 OCR 批处理。
此时 `src.txt` 会写明「无可用源物理行」，只能靠 MD 自身的段落语义与上下文判断，判据更弱，**存疑时倾向于不动**。

## 2. 四类典型排版缺陷

### 缺陷 A：引导句被孤立（最常见、最该修）

**特征**：某段以 `：` `；` 结尾，下一段是它的正文内容。

```
综上所述：

蔡英文毁掉统一的最大阻碍国民党，为民进党卖台扫清了障碍。……
```

**成因**：源 PDF 的行尾标点被当成段落边界。「综上所述：」后面本该紧跟内容。

**判据**：`src.txt` 中该段最后一行是 `[断]`，且下一行内容与它构成「总—分」关系。

**修法**：把引导句和下一段**合并成一段**——具体是**删掉两者之间的空行**（段落边界），
两段文本直接相连。不要在两段之间加空格或换行。

**⚠️ 必须排除的例外**：如果下一段是**列举列表**，
那「引导句 + 列举列表」是作者本来的结构，**不是缺陷，不要合并**。

```
我们看看拓跋什翼键的儿子们：
拓跋寔君，拓跋什翼犍庶长子。
拓跋寔，拓跋什翼犍次子，母昭成皇后慕容氏。
……（连续 8 个儿子）
```

**判断要点**：列举项**不一定以序号开头**（上面这组是以人名开头的）。
可靠的判据是**形态一致性**——引导句之后连续若干段长度相近、内容平行
（都是「名字，描述」的同构句）。若成立，是列表；若下一段是展开论述
（如「综上所述：」后接一大段评论），才是引导句被孤立。

**⚠️ 机械层面无法可靠区分这两者**：`precheck.py` 因此只报「证据」
（下一段是列举项/普通段落、后续段落长度是否一致），**不下结论**。
必须由你对照 `src.txt` 与上下文判断。

**实测规模**：存量库 300 处引导句，分布在 127/1241 篇（10.2%）文件里。
其中约 35 处是「引导句 + 列举列表」（不该修），其余需逐篇判断。

### 缺陷 B：多段并成一段（该断未断）

**特征**：单段异常长（> 400 字），段内塞了多个完整句子。

**判据**：`src.txt` 里该段覆盖的源行区间中，**有多个 `[断]` 标记**——说明本该分段的地方被拼到了一起。

**典型陷阱**：中文长句本来就长。存量库段落长度 p50=51 / p90=118 / p99=204 / max=726，
**超过 400 字只有 6 篇**。所以「长」本身不是问题，「长且内部有多处该断点」才是。

**修法**：在对应的 `[断]` 位置断开。

### 缺陷 C：一句被切成两段（不该断却断）

**特征**：后一段很短（< 30 字）且末尾不是终止标点——典型残句。

**判据**：`src.txt` 里这两行**之间没有 `[断]`**（即前一行是 `[续]`，行尾无终止标点），
说明它们本该被拼接，却被拆开了。

**典型误判陷阱**：短段本身可能是合法的独立段落（列举项「乙、推动军公教年金改革」、
引文「虽千万人吾往矣」）。判据是 **`src.txt` 的 `[断]`/`[续]` 标记**，不是长度。

### 缺陷 D：小标题被并进正文

**特征**：正文里出现「（一）」「【1】」「先讲结论：」这类独立小标题，紧跟着一大段正文。

**修法**：给小标题单独成段并加 `## ` 前缀。

**注意**：`md_layout.render` 支持 `enhancements`（段落索引 → `heading`/`quote`），
但**转换器路径不加载 enhancements**——它只在知识库侧 `format_chaguan_md.py` 的批处理里生效。
转换器产出的文件里，`## ` 需要在 agent 修复时直接写入 MD。

## 3. 修复的机械形态（务必理解，否则修复会「不稳定」）

已排版 MD 里，**段落边界 = 空行**。`md_layout.parse` 会把空行密度 > 0.15 的文件判为
`strict_blank=True`（存量库 1239/1241 篇都是），此时 `rebuild()` **以空行为准断段**，行尾标点不再起作用。

这带来两个直接结论：

1. **合并两段 = 删掉中间的空行**，两段文本直接相连。
   写成 `A：\nB。`（保留换行但去掉空行）会变成两个独立行，重新排版时又会被拆开 →
   `verify_fix.py` 报「再次排版幂等」失败。
   正确写法是 `A：B。`（一行，中间无空行）。

2. **拆分一段 = 在中间插入空行**。

**验证过的正确修法示例**：

```
改前：                          改后：
我们看看拓跋什翼键的儿子们：      我们看看拓跋什翼键的儿子们：拓跋寔君，拓跋什翼犍庶长子。
                                拓跋寔君，拓跋什翼犍庶长子。
```

（原文中间有一个空行，合并后删掉它，两段文本直接相连。）

**字符守恒**：合并/拆分都只动空行和段落边界，正文字符序列必须**完全不变**——
`verify_fix.py` 会用 `body_chars()` 逐字比对，并报出首个差异位置。

## 4. 不属于缺陷的现象（不要动）

| 现象 | 为什么不是缺陷 |
|---|---|
| 段内「。+汉字」 | 中文书写常态，99.8% 文件命中 |
| 段落长（< 400 字） | p90=118，p99=204，正常分布 |
| H1 与文件名不一致 | 42 篇全是 `JM06`/`JM6`、日期后缀等良性差异 |
| 无 `> 来源`/`> 原文件` 元数据 | 存量库 1113/1241 篇就没有，是既有状态不是新缺陷 |
| `## ` 小标题、引用块 | 存量库 3 篇有 `##`、131 篇有 `>` 引用块，是知识库侧的增强标记，转换器不产这个 |
| OCR 噪声（「浮两，这就没完没」） | 早期文章 OCR 准确率约 90%，其残句多为 OCR 噪声而非排版错误 |

## 5. 硬红线：绝对不能做的事

1. **不得改动任何正文字符**。修复只能增删「空行」和「段落边界」（Markdown 结构标记）。
   正文字符序列必须与修复前**完全一致**。
   - 反例：把「姜维」改成「姜维」→ 违规。
   - 正例：把两段合并成一段 → 合规。
   - **理由**：知识库是原文归档，字符守恒是可追溯性的根基。

2. **不得补字**。上游提取丢失的内容不要在 MD 里脑补。`src.txt` 同样断的，说明是
   **上游提取问题，不是排版问题**——记录并上报，不要在 MD 里补。

3. **不得改动 H1 标题文字**。

4. **不得删除 `> 来源` / `> 原文件` 元数据行**。

5. **不得把 PDF 原文覆盖进 MD**。知识库 MD 里的姓名是**匿名化后**的
   （如 `姜维` ↔ PDF 的 `姜维`），源 PDF 的字符不能直接写回 MD。

6. **不得在本流程中改 `md_layout.py` 的规则**，除非问题在**多个文件上以同一模式复现**。
   规则改动必须：
   - 同步改 `scripts/md_layout.py` **和** 知识库侧 `历史学习/scripts/format_chaguan_md.py`
   - 两边同时 bump `RULE_VERSION`
   - 跑 `scripts/test_md_layout.py`，退出码非 0 不得继续

## 6. 复查流程

对每个被标记的文件：

1. 读 `md.md`（待检对象）、`src.txt`（判断依据）、`para_map.json`（段落↔行号映射）
2. 定位可疑段落（用 `precheck.py` 报的段落序号 + `para_map.json` 查源行区间）
3. 看源行的 `[断]`/`[续]` 标记判定：
   - 段末是 `：`/`；` 且源行标 `[断]` → 缺陷 A（引导句被孤立）
   - 段内源行区间含多个 `[断]` → 缺陷 B（多段并成一段）
   - 下一段很短且源行标 `[续]` → 缺陷 C（被切开）
4. 判定是缺陷 → 在 `md.fixed.md` 上改（**不直接改知识库文件**）
   - 合并两段：删掉中间空行，两段文本直接相连（见 §3）
   - 拆分一段：在中间插入空行
5. 判定正常 → 不动；存疑 → 倾向于不动
6. 跑 `verify_fix.py --before md.md --after md.fixed.md`
7. 门禁全绿 → 用 `md.fixed.md` 覆盖知识库文件；有任何一项失败 → 放弃该篇修复，记录原因

## 7. 判定速查表

| 观察到的现象 | 先别急着改 | 判定方法 |
|---|---|---|
| 段落很长 | 可能是本来就长 | 源行区间里有多个 `[断]` → 才拆 |
| 段落很短 | 可能是独立短段 | 源行是 `[续]` → 被切断；是 `[断]` → 合法 |
| 段末是冒号 | **最该修的一类** | 下一段是否是其内容 → 是则合并 |
| 末尾没标点 | 可能是引文/列举项 | `src.txt` 同位置也断 → 上游问题，不补字 |
| 段内多句 | 中文常态 | 需源行 `[断]` 佐证 |
| H1 与文件名不同 | 良性 | `JM06`/`JM6`、日期后缀 → 不动 |
